# 바이브 로그 쇼츠 제작 스펙 (2026-09-09 샘플 승인 기준, 보이스 설정 같은 날 갱신)

샘플로 확정한 규칙. 2단계(쇼츠 파이프라인) 구현 시 Remotion 템플릿·오디오 합성의 기준 문서.
프로토타입 HTML: `docs/shorts-prototype.html` (Ship it 템플릿, 9:16, 페이지 자체가 타임라인을 재생함 — Remotion 컴포넌트로 옮길 때 참고).

## 포맷

- 1080×1920 (9:16), 30fps, H.264 yuv420p, AAC 192k
- 길이 30~45초. 구성: 커밋 콜드오픈(2초, 재료 있을 때만) → 훅(3~4초) → 뭘 만들었나 → 화면 데모 → 삽질 → 다음 할 것 → 엔드카드(2~3초)
- 언어: 한국어 원본 + 영어 버전 별도 렌더
- 톤: 존댓말

- **데모 화면↔내용 매칭 (2026-09 추가)**: 데모 화면은 이야기와 맞아야 한다 —
  이전에는 일반 투어(홈→스크롤→링크)를 시간순으로 잘라 얹어서 문장과 화면이
  무관했다 (Jessi 지적: "그냥 막 넣는 것 같아"). 이제 ① 대본 생성이 배포
  사이트의 실제 링크 목록을 받아 build·demo 문장마다 `screen`(경로)을 고르고
  ② 녹화가 그 화면들을 순서대로 찍으며 구간 시각을 남기고
  (`<date>.<lang>.segments.json`, readyAt 기준) ③ 렌더가 phone 블록의 문장
  screen과 구간을 매칭해 그 지점부터 재생한다. 실존 경로만 통과(404 소재
  방지), 같은 화면 재사용 시 구간 안에서 이어 재생. screen이 없거나 구버전
  녹화면 기존 시간순 자르기로 폴백. `vibelog.json`의 demo.steps는 언제나 우선.
  **구간 시작은 스크린샷을 찍은 뒤로 잡는다** — 녹화 중 `page.screenshot()`이
  수 초씩 걸리는데(실측 15.06초 구간 중 앞 5초), 그 정지 구간이 구간 머리에
  들어가면 데모 블록(내레이션 두어 문장, 2~5초)이 멈춘 화면만 보여 주고
  끝난다 ("계속 멈춰 있다가 마지막에 휙 스크롤 되다가 사라져" — Jessi).
- **데모 샷 3종 로테이션**: 매 데모 장면이 같은 폰 컷이면 중반이 늘어진다 —
  phone(베젤+켄 번스) / band(베젤 없는 와이드 밴드 크롭 830px + 세로 팬) /
  duo(폰 두 대를 겹치기 — 앞은 문장과 매칭된 주 화면, 뒤는 녹화된 **다른**

  **녹화가 390×844라 1080 풀블리드는 화질이 무너진다 — 새 샷은 업스케일 ~2배 이내로만.**

## 다이어그램 5종 (2026-09 추가)

화면 녹화로는 보여 줄 수 없는 **"원리"**를 그리는 장면. 원인·구조·전후를 말로만
설명하는 문장(주로 fail의 원인, build의 해결)에 붙는다. 기능·동작처럼 화면으로
보여 줄 수 있는 것에는 붙이지 않는다 — 그건 demo다.

**자유 작도는 없다.** 대본은 종류와 라벨만 고르고 그림은 컴포넌트가 그린다
(`video/src/Diagram.tsx`). 예전에 도형을 자유 조립하게 했다가 매 편 품질이
널뛰었던 것의 교훈 — 어휘를 고정해야 품질이 고정된다.

| 종류 | 언제 | labels |
|---|---|---|
| `numberline` | 임계값·범위가 문제였을 때 | [범위 이름, 문제였던 값, 고친 값] |
| `fork` | 하나가 둘로 갈릴 때 | [출발, 왼쪽 결과, 오른쪽 결과, 왼쪽 이름, 오른쪽 이름] — **답을 오른쪽에.** 강조는 그쪽에 켜진다 (`"pick": 1`이면 왼쪽) |
| `beforeafter` | 방식을 갈아치웠을 때 | [전-시작, 전-결과, 후-시작, 후-결과] |
| `sets` | 전체 중 일부가 겹칠 때 | [왼쪽 집합, 오른쪽 집합, 겹친 값] |
| `pipeline` | 단계가 순서대로 흐를 때 | [단계 2~5개] |

- **편당 최대 2개** (`capDiagrams`). 그림이 문장보다 많으면 영상이 도식만 남는다.
- 이웃 편(직전·다음)이 쓴 종류를 프롬프트로 받아 연달아 같은 그림을 피한다.
- 라벨은 짧게 — 한 칸에 한글 10자 안팎. 숫자선의 값 둘은 **6자 이내**(축 위
  좁은 자리라 길면 두 줄로 터진다). 길면 `fitFont`가 글자를 줄이고, 줄바꿈은
  `keep-all` + `text-wrap: balance`로 고르게 나눈다 — 한 글자만 떨어져 나가
  점 위에 얹히던 사고가 있었다.
- 그리기 규칙 (샘플 검수에서 확정): 선은 방향을 가지고 그려진다(가로 왼→오,
  세로 위→아래, 원은 12시부터 시계방향 — `pathLength={1}`로 길이를 정규화해
  dashoffset을 0~1로 쓴다). 화살표는 도착 도형 **앞에서 멈춘다**. 박스 배경은
  **불투명**(반투명이면 뒤 선이 비친다 — 민트는 배경에 미리 합성).
- 형태·폰트는 테마를 따른다: 모서리 `th.radius`, 본문은 `FONT_SANS`
  (JetBrains Mono에는 한글이 없어 대체 글꼴로 떨어진다. 전/후 표시만 모노).

## 자막 규칙 (핵심)

1. 문장 단위 한 덩어리. 화면에 최대 두 줄. 세 줄 되면 문장을 쪼갠다. `word-break: keep-all`.
2. 단어는 흐림(opacity .3) → 또렷(1)으로 말하는 속도에 맞춰 순서대로 켜진다. 페이드 ~0.28s.
3. 문장당 강조 키워드 1~3개를 민트색으로. 키워드는 켜지는 순간 색이 들어가고 **문장이 끝날 때까지 유지**. 단어별 색 반전(현재 단어만 색) 금지 — 번쩍임의 원인.
   **켜지는 단어는 문장 단어 수의 절반을 넘지 않는다.** 한국어 훅은 서너 단어라 두 개만 걸려도 통째로 칠해진다 — 훅은 강조 하나. 개수 제한만으로는 못 막아서 `scripts/script.ts`의 `capCoverage`가 생성 결과를 잘라낸다.
4. 음성이 끝나도 자막은 **다음 문장 시작 직전(−0.15s)까지 잔류**. 최소 0.4초 보장. 마지막 문장은 엔드카드 위에 2초 잔류.
5. 대본 생성 시 Claude에게 키워드를 마킹하게 한다 (프로토타입은 `^단어` 표기).
6. 타이밍은 ElevenLabs 타임스탬프(단어 단위)로 잡는다. 샘플에서는 무음 구간 검출로 대체했음.

## 데모 화면 — 대본이 맞히지 않는다, 녹화기가 찾는다

매 편 되돌아온 지적이 전부 이 한 줄로 모인다: **말하는 것과 화면이 맞아야
한다.** 여기 적은 것은 규칙이 아니라 실제로 틀렸던 것들의 목록이다.

### 원칙

1. **연출은 내용이 정한다.** 정해둔 것을 돌리거나 짜맞추지 않는다 (Jessi).
   폰/밴드/듀오를 `(day + 순번) % 3`으로 돌리던 것을 없앴다 — 문장이 `shot`으로
   고른다: `focus`(한 곳을 크게) / `whole`(전체) / `compare`(두 화면을 견줌).
2. **대본은 경로를 맞히지 않는다.** 대본은 사이트를 본 적이 없다. 문장이
   말하는 것을 `find`에 적고, **그것이 어느 화면에 있는지는 녹화기가 찾는다**
   (`scripts/record.ts`의 `locateOnPage`). `screen`은 힌트일 뿐이다.
3. **찾는 방법은 웹 표준과 크기뿐이다.** 사이트별 사전을 만들지 않는다
   (Jessi: "이렇게 매번 커스텀할 게 아니야"):
   ① 보이는 글자 → ② 접근 이름(`aria-label`·`alt`·`title`) → ③ 그 화면에서
   가장 큰 그림(svg·img·canvas). ③이 있어야 글자 없는 도장·그래프를 가리킬 수
   있다 (apart의 도장은 홈 배경의 `aria-hidden` SVG다).
4. **가리킨 것을 붙잡는다.** 구간 시작점만 맞추고 계속 스크롤하면 문장이 말하는
   동안 화면이 그 요소를 지나쳐 흘러간다 — 가장 오래 되돌아온 지적이다.
   `find`가 있는 정류장은 그 자리에 머물고(6px만 흔든다), 밴드 크롭의 세로 팬도
   끈다. `find`가 없는 정류장만 화면 전체를 훑는다.
5. **화면에 표시를 얹는다.** 가운데로 올려 놔도 어디를 보라는 건지 모른다.
   녹화용 브라우저에서만 민트 테두리 + 바깥을 살짝 덮는다 (`data-vl-ring`,
   다음 정류장에서 지운다). 사이트는 건드리지 않는다.
6. **엉뚱한 화면 > 같은 화면 반복 > 빈 화면** 순으로 나쁘다. 맞는 화면이 없으면
   비운다. 대신 **화면을 못 고른 문장에는 다이어그램을** 붙인다 — 빈 화면은
   마지막 수단이다. 빈 자리를 콜드오픈 모양으로 메우는 것은 짜맞추기다
   (Jessi: "그 모양을 그대로 그리라는 게 아니라 내용에 맞는 뭔가를").
7. **duo(폰 두 대)는 서로 다른 화면이 실제로 녹화됐을 때만.** 하나뿐이면
   같은 화면이 겹쳐 나온다 — 그때는 크게 보여준다. 정류장이 한 화면뿐이면
   녹화가 다른 화면을 하나 더 찍어 재료를 만든다.
8. **삽질 문장도 화면을 받는다.** `fail`을 카드·다이어그램 전용으로 두면
   "도장 이야기를 하는데 도장이 한 컷도 없는" 편이 구조적으로 보장된다.

### 구간 매칭

녹화는 정류장마다 `{path, find, start, end}`를 `<date>.<lang>.segments.json`에
남기고, 렌더(`video/src/ShipIt.tsx`)가 문장의 `screen`+`find`로 그 구간을 찾아
재생한다. 화면이 바뀌면 블록을 끊는다 — 합치면 뒤 문장이 고른 화면이 버려진다.

## 테마 — 레포마다 다른 얼굴, 같은 문법

레포는 **topic `vibelog-theme-<이름>`** 하나(예: `vibelog-theme-signal`)로 영상 테마를 고른다. `vibelog.json`의 `"theme"`도 되고, 둘 다 있으면 json이 우선. 안 고르면 terminal.
채널 아이덴티티(장면 구조·자막 규칙·푸터·진행 바)는 모든 테마 공유 — 팔레트·키워드 강조 방식·카드/배지 형태·배경 처리만 바뀐다. 토큰은 `video/src/theme.ts`.

| 이름 | 톤 | 키워드 강조 | 어울림 |
|---|---|---|---|
| `terminal` | 다크 + 민트 글로우 (기본) | 민트 컬러 | 도구·자동화 |
| `blueprint` | 딥 네이비 + 격자, 각진 모서리 | 블루 + 밑줄 | 인프라·API |
| `signal` | 웜 블랙 + 상단 오렌지 엣지 | 오렌지 (before 취소선) | 소비자 앱·운동 |
| `paper` | 라이트 (유일), 종이 카드 | 그린 형광펜 | 글쓰기·정리 |
| `highlighter` | 흑백 브루탈리스트 | 노랑 마커칠 | 실험작·장난감 |

- 배경음악: `video/assets/music/`의 고정 트랙 5종을 재사용한다 (API 미사용 — 크레딧·일관성).
  톤: `ship-it`(기본, 담담한 전진) / `upbeat`(배포·성공) / `tense`(큰 삽질) / `calm`(문서·정리) / `playful`(실험·장난기).
  대본(script.ts)이 그날 이야기 분위기로 `music` 톤을 고르고, 없으면 템플릿 트랙 → 아무 트랙 순 폴백.
  트랙 생성 프롬프트 계보: "minimal lo-fi electronic ~90 BPM, instrumental, 45s" 계열에서 톤별 변주 (eleven_music_v2).
- 믹스: 음악 volume 0.20, 내레이션 사이드체인 더킹(threshold .03, ratio 5, attack 40ms, release 500ms), 음악은 끝 3.5초 페이드아웃. amix normalize=0.

```
ffmpeg -i video.mp4 -i narration.mp3 -i music.mp3 -filter_complex "\
[1:a]adelay=500|500,apad=whole_dur=DUR,asplit=2[n1][n2];\
[2:a]atrim=0:DUR,volume=0.20,afade=t=out:st=DUR-3.5:d=3.5[m];\
[m][n1]sidechaincompress=threshold=0.03:ratio=5:attack=40:release=500:makeup=1[d];\
[d][n2]amix=inputs=2:duration=first:normalize=0[a]" -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k out.mp4
```

## 템플릿 3종 (2026-09 전부 구현) + 자동 로테이션

같은 구성이 반복되면 채널이 단조롭다 (Jessi 지시). 템플릿 = 서사 구조 + 콜드오픈 문법 + 톤.
장면 컴포넌트(훅·폰·삽질 카드·자막·푸터)는 셋이 공유한다.

| | ship-it | fail (오늘의 삽질) | before-after |
|---|---|---|---|
| 서사 | 만든 것 → 데모 → 삽질 | 사고 선언 → 원인 → 고침 → 증명 | 어제는 이랬다 → 오늘 바뀐 것 → 화면 |
| 콜드오픈 | `git log` 커밋 5줄 | ✗ 사고 한 줄 (warn색) | `git diff` — before / + after |
| 컷 차이 | 기본 | ✗ 콜드오픈 + FAIL 배지 | 삽질 카드 좌우 2열 대비 |

- **키워드 색은 템플릿이 못 바꾼다** — 키워드 강조는 언제나 테마의 규칙(terminal이면
  민트)이다. fail 훅을 warn색으로 바꿨다가 테마 아이덴티티가 깨져 반려됐다 (Jessi).
- 대본 생성(script.ts)이 이야기에 맞는 템플릿을 고른다. **직전 편 템플릿을 프롬프트로
  받아, 이야기가 강하게 요구하지 않는 한 직전 편과 다른 것을 고른다** — 자동 로테이션.
- fail·before-after의 콜드오픈 재료는 failCard(before/after)라 해당 템플릿이면 필수.
  재료가 없으면 log 콜드오픈으로, 커밋도 없으면 콜드오픈 없이 폴백 (`coldOpenKind`,
  scripts/shorts-types.ts — scripts와 video가 같은 판정을 써야 영상 길이가 맞는다).

## 재생성 (덮어쓰기)

자막 규칙·프레임 디자인·대본 프롬프트를 고친 뒤에는 이미 발행된 글의 영상을 다시 만들어야 한다. 꽤 빈번하므로 전용 진입점이 있다.

- **GitHub → Actions → devlog → Run workflow**, `regen` 입력에 `vibelog/2026-09-10` 형식으로 쓰고 실행. 날짜를 빼고 `vibelog`만 쓰면 그 레포의 최신 글.
- 대본→음성→녹화→렌더→업로드 전 단계를 다시 돌고, 같은 Blob 키에 덮어쓴다(`allowOverwrite`). 글(md)은 건드리지 않는다.
- 로컬: `npx tsx scripts/shorts.ts vibelog/2026-09-10`.
- 레포마다 따로 돌린다 — 입력이 글 하나만 받는다.
- 썸네일은 regen이 알아서 새 mp4에서 다시 뽑아 올린다. 영상은 그대로 두고
  **썸네일 프레임만** 바꾸고 싶을 때는 `poster` 입력(`vibelog/2026-09-09`)을
  쓴다 — 대본·음성 재생성이 없어 API 비용 0.
- 대본도 다시 생성되므로 프롬프트가 바뀌었으면 문장 자체가 달라질 수 있다 — 의도된 동작.
