## 뭘 했나

밤마다 아파트 목록과 가짜 이름을 조금씩 채우게 했습니다. 실제 아파트 정보를 주는 공공 서비스가 하루 5,000건까지만 내주기 때문에 한 번에 다 받을 수 없습니다. 그래서 매일 밤 자동으로 조금씩 받아 옵니다. 받는 순서는 남은 양이 적은 지역부터로, 부산, 대구, 인천, 경기 순입니다.

## 왜

큰 지역을 먼저 걸면 몇 주 내내 그 지역만 받게 되고 나머지는 계속 빈약하게 남습니다. 적게 남은 곳부터 끝내야 지역별로 고르게 찹니다. 같은 밤에 가짜 이름도 새로 만듭니다. 진짜 목록이 늘면 지어낸 줄 알았던 이름이 실제로 있는 단지로 드러나 빠지기 때문에, 보충하지 않으면 가짜 쪽만 계속 줄어듭니다.

## 삽질 포인트

함정 하나를 미리 발견해서 피했습니다. 새로 받은 목록으로 기존 목록을 통째로 갈아 끼우면, 손으로 직접 넣어 둔 단지들이 매일 밤 조용히 사라집니다. 그래서 갈아 끼우지 않고 더하는 방식으로 했습니다.

## 다음 할 것

부산이 끝나면 대구, 인천, 경기 순으로 넘어갑니다. 며칠 뒤 지역별 문제 수가 고르게 늘었는지 확인하겠습니다. 목록이 아예 0건으로 나오는 지역 2곳은 따로 방법을 찾아야 합니다.

## What I did

Each night the list of real apartments and the pool of made-up names now fill up a little. The public service that hands out real apartment data caps me at 5,000 records a day, so I can't take it all at once. The nightly run pulls a small batch instead. It starts with the regions that have the least left: Busan, then Daegu, then Incheon, then Gyeonggi.

## Why

If I started with the biggest region, I'd spend weeks on that one region while the rest stayed thin. Finishing the small ones first keeps every region evenly stocked. The same night also produces new fake names. As the real list grows, names I thought were invented turn out to be actual places and get dropped, so without a top-up the fake side would only shrink.

## Rabbit holes

I caught one trap before it bit. If each night's fresh list simply replaced the old one, the entries I had added by hand would quietly disappear every night. So the new data gets added on top instead of replacing anything.

## Next up

Once Busan is done it moves on to Daegu, Incheon, and Gyeonggi. In a few days I'll check whether the question counts grew evenly across regions. Two regions return zero results entirely, and those need a different approach.
