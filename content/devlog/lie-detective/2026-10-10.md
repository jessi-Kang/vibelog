## 뭘 했나
용의자의 답변 규칙을 브라우저에서 서버로 옮겼습니다. 거짓말 탐정은 인물들에게 자유롭게 질문하며 사건의 진실을 밝히는 모바일 웹 추리 게임입니다. 게임을 열면 화면을 그리는 코드가 플레이어의 브라우저로 통째로 내려옵니다. 지금까지는 인물이 질문에 어떻게 답할지 정하는 규칙도 그 코드에 같이 들어 있었습니다. 이제 브라우저로 내려오는 코드에는 인물 소개만 있고, 답은 서버가 정해서 보내 줍니다. 그러려고 한 장짜리 HTML이던 게임을 Next.js(화면과 서버를 함께 만드는 도구) 프로젝트로 옮겼습니다. 이 밖에 구글 로그인을 하면 수사 기록과 사진을 계정에 저장해 다른 기기에서 이어 볼 수 있게 했습니다.

## 왜
브라우저에서 "소스 보기"만 열면 누구나 그 규칙을 읽을 수 있었습니다. 용의자가 어디서 거짓말하는지 미리 알면 추리 게임이 성립하지 않습니다. 그래서 배포(게임을 인터넷에 올리는 일) 전에 저절로 도는 검사도 붙였습니다. 브라우저로 내려갈 코드에 사건의 정답이 들어 있으면 배포를 멈춥니다.

## 삽질 포인트
Vercel(배포를 맡아 주는 서비스)에 올리려는데 빌드(배포 전에 코드를 묶는 단계)에서 멈췄습니다. 문제는 로그인과 수사 기록 저장을 맡은 서버 코드에 있었습니다. 데이터베이스에 보내는 명령은 따옴표 같은 기호로 앞뒤를 감쌉니다. 그 기호 앞에 필요 없는 역슬래시(\)가 붙어 감싸는 역할을 못 했습니다. 그래서 빌드가 명령이 어디서 끝나는지 찾지 못했습니다. 역슬래시를 떼고 다시 빌드해 확인했습니다.

## What I did
I moved the suspects' answer rules from the browser to the server. Lie Detective is a mobile web mystery game where you question characters freely to uncover what really happened. When you open the game, the code that draws the screen is downloaded in full to the player's browser. Until now, the rules deciding how each character answers were bundled into that same code. Now the code sent to the browser holds only the character introductions, and the server decides the answers and sends them back. To do this, I moved the game from a single HTML file to a Next.js (a tool for building both the page and the server) project. I also added Google sign-in, so case notes and photos can be saved to your account and picked up on another device.

## Why
Anyone could read those rules just by opening "view source" in the browser. If you know in advance where a suspect lies, the mystery falls apart. So I also added a check that runs automatically before each deploy (putting the game online). If the code headed to the browser contains the case's answers, the deploy stops.

## Rabbit holes
When I tried to deploy to Vercel (a service that hosts the game), it stopped at the build step (where the code gets bundled before deploying). The problem was in the server code for sign-in and saving case notes. Commands sent to the database are wrapped at both ends by a quote-like symbol. An unnecessary backslash (\) in front of that symbol stopped it from wrapping anything. So the build couldn't tell where the command ended. I removed the backslash and ran the build again to confirm.
