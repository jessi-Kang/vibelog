## 뭘 했나

두 번째 프로젝트를 이 블로그에 붙였는데, 목록에 나타나지 않았습니다. 그걸 나타나게 만드는 데 하루를 썼습니다.

이제 프로젝트에 표시만 달아 두면 30분 안에 목록에 올라옵니다. 설명을 나중에 채워도 반영됩니다. 공개 주소도 직접 적지 않아도 알아서 찾아옵니다.

덧붙여 이번 주와 오늘 커밋 수가 항상 100으로 멈춰 있던 것을 고쳤고, 네 자리 숫자에 콤마를 넣었습니다. 글 아래 재료로 붙는 커밋 목록도 그날 것 전부를 싣게 했습니다.

## 왜

손을 대야 하는 곳이 남아 있으면 자동 발행이라고 부를 수 없습니다. "커밋 16개로 작성했다"고 쓰면서 정작 목록에 8개만 보이는 것도 앞뒤가 안 맞았습니다.

## 삽질 포인트

새 프로젝트가 안 보인 이유는 두 겹이었습니다. 프로젝트를 찾는 방식이 검색에 의존했는데, 새로 만든 것은 검색에 늦게 반영됩니다. 그래서 검색 대신 제 프로젝트 목록을 직접 훑도록 바꿨습니다. 다른 하나는 확인 시점이었습니다. 프로젝트를 찾는 일이 밤 11시 실행에만 묶여 있어서, 낮에 등록해도 밤까지 기다려야 했습니다.

주소를 자동으로 찾게 하자 다음 문제가 왔습니다. 시험용으로 잠깐 올려 둔 것까지 전부 "공개됨"으로 표시된 겁니다. 그래서 주소만 있으면 미리보기, 실제로 공개를 선언했으면 공개됨으로 나누었습니다.

한 프로젝트에 배포 주소가 두 개 붙어 있던 경우도 있었습니다. 나중 것이 이겨서 엉뚱한 주소를 대표로 잡았고, 첫 번째를 지키도록 고쳤습니다.

## 다음 할 것

오늘 밤 자동 실행 기록을 보고 주소 찾기가 제대로 동작했는지 확인합니다. 확인용 기록을 한 줄씩 남겨 두었습니다.

## What I did

I added a second project to this blog, and it simply never appeared in the list. Making it appear took the whole day.

Now, once a project is tagged, it shows up within 30 minutes. Filling in the description later gets picked up too. The public address is found automatically, without me typing it in.

On top of that, the weekly and daily commit counts had been stuck at 100 forever, so I fixed that, and added commas to four-digit numbers. The commit list attached to each post now carries every commit from that day.

## Why

If there is still a spot where I have to reach in by hand, it is not really automatic publishing. And writing "built from 16 commits" while only showing 8 in the list did not add up.

## Rabbit holes

There were two reasons the new project stayed invisible. Finding projects relied on search, and freshly created ones take a while to show up in search. So I switched to walking through my own project list directly. The other reason was timing: the check only ran during the 11pm job, so anything registered during the day had to wait until night.

Automatic address detection brought the next problem. Things I had put up briefly just to test were all being marked as "live." So I split it in two: an address alone means preview, and an actual release announcement means live.

One project also had two deploy addresses attached. The later one won and grabbed the wrong address, so I made it keep the first.

## Next up

I will check tonight's automatic run to see whether address detection worked. I left one line of record for each step so it can be judged right away.
