## 뭘 했나

밤에 글을 쓸 때 가장 최근에 작업한 [[브랜치|코드를 따로 갈라 작업하는 갈래]]를 읽게 했습니다. 이 블로그는 밤마다 프로젝트별로 글을 쓸지 정합니다. 그 결과는 홈 화면에 프로젝트마다 한 줄씩 남는데, 이것을 실행 기록이라고 부릅니다. 그런데 지난밤 실행 기록에는 프로젝트가 6개라고 나왔는데 줄은 5개뿐이었습니다. 빠진 것은 제가 만들고 있는 프로젝트 중 하나인 거짓말 탐정이었습니다. 이제 그 프로젝트의 작업도 읽습니다. 글을 안 쓴 프로젝트도 이유를 꼭 한 줄 남깁니다.

## 왜

거짓말 탐정은 그날 [[커밋|작업을 한 덩어리씩 저장하는 지점]] 103개를 올렸습니다. 그런데 글은 나오지 않았고, 실행 기록에는 이름조차 없었습니다. 이름이 빠지면 그날이 지난 뒤에는 무슨 일이 있었는지 다시 찾기 어렵습니다.

## 삽질 포인트

처음에는 그 프로젝트가 어디로 갔는지조차 알 수 없었습니다. 알고 보니 커밋을 모을 때 [[레포|코드를 모아 두는 저장소]]의 [[기본 브랜치|레포를 열면 처음 보이는 브랜치]]만 읽고 있었습니다. 거짓말 탐정은 preview라는 다른 브랜치에서만 작업하고, 기본 브랜치에는 합치지 않았습니다. 그래서 새 커밋이 0개로 세어졌습니다. 새 커밋이 없는 프로젝트는 실행 기록에 줄을 남기지 않아서 이름까지 사라졌습니다.

이제는 브랜치마다 마지막으로 커밋한 시각을 보고 가장 최근 브랜치를 읽습니다. 프로젝트마다 작업을 기본 브랜치에 올려 달라고 하는 방법은 쓰지 않았습니다. 레포를 등록한 사람이 할 일이 늘고, 브랜치를 다시 나누면 또 빠지기 때문입니다.

## What I did

The nightly run now reads the most recently active [[branch|a separate line of work in the code]]. Every night this blog decides, project by project, whether to write a post. The result shows up on the home page as one line per project, and I call that the run log. Last night's run log said there were 6 projects, but it listed only 5. The missing one was Lie Detective, one of the projects I'm building. Now its work gets read too. Every project that doesn't get a post also leaves one line saying why.

## Why

That day Lie Detective pushed 103 [[commits|saved chunks of work]]. Yet no post came out, and its name wasn't even in the run log. When a name drops out, it's hard to work out later what happened that night.

## Rabbit holes

At first I couldn't even tell where the project had gone. It turned out that when gathering commits, I only read each [[repo|the storage where a project's code lives]]'s [[default branch|the branch you see first when you open a repo]]. Lie Detective was working only on a branch called preview and never merged into the default one. So it counted zero new commits. Projects with no new commits didn't get a line in the run log, so the name vanished entirely.

Now I look at when each branch was last committed to and read the newest one. I didn't ask each project to put its work on the default branch. That adds work for whoever registers the repo, and splitting branches again would break it again.
