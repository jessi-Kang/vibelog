## What I did
A new project's first post now introduces the project. Now, when a new project comes in, the AI reads its planning doc and code first. Then it writes an intro post as the first post: what I want to build, and for whom. Every later post gets a one- or two-sentence project description under its title, and tapping it opens the intro.

## Why
Until now, the first post jumped straight into what got done that day. Newcomers had to read without knowing what the project was building. One project's first post never said what it was building, all the way to the end. For the same reason, project names now show differently. Before, the site showed the English name given to the [[repo|the place where the code is stored]], like "lie-detective." Now it shows the real service name, like "Lie Detective."

## Rabbit holes
The first 5 intro posts were far too detailed. They listed screens and features. Lie Detective is a service with answers, and its intro even told you how to find them. The AI writes by following instructions I've written. Those instructions asked for what had been built so far and what comes next. They were made for a project that was already well along. But an intro is written right when a project is registered. I took the 5 posts down and changed it to look only at the repo as it was at registration and say only what it sets out to build. Answers and secrets stay out, even if the AI saw them in the code.

## Next up
I'll read the rewritten intros and check that they only say what each project sets out to build. I'll watch that feature lists and secrets don't creep back in.
