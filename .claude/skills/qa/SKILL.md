# vibelog QA

이 문서는 규칙집이 아니라 **실제로 되돌아온 지적들의 목록**이다. 전부 Jessi가
한 번 이상 직접 잡아낸 것이다. 같은 것을 두 번 잡히지 않는 게 목표다.

**전제 둘.**
- "타입체크 통과"·"빌드 성공"은 검증이 아니다. 렌더해서 보지 않은 것들이 전부
  되돌아왔다.
- **푸시는 끝이 아니다.** 배포가 READY가 되는 것까지가 한 작업이다.

---

## 순서

### 0. 고치기 전에

- **디자인·아이콘은 시안을 먼저 보여 주고 고르게 한다.** 고친 뒤 "어떠세요"는
  순서가 틀렸다 ("시안을 다시 줘야지 왜 적용해?"). 두 가지 이상을 뽑아
  이미지로 보여 주고, 고른 다음에 적용한다.
- **모르는 값은 묻는다.** 외부 주소·계정·도메인을 그럴듯하게 지어내면 엉뚱한
  곳으로 간다.
- **손품이 늘어나는가**를 먼저 본다. 늘어나면 다른 방법을 찾는다.

### 1. 바뀐 파일에 detect

```
.claude/skills/impeccable/scripts/impeccable detect --json <바뀐 파일들>
```

지적 0건까지. (강조용 왼쪽 막대 `border-l-2` 같은 흔한 장식이 여기서 걸린다.)

### 2. 기계 검사 — 렌더해서 잰다

```
npm run build && npx next start -p 3210
node .claude/skills/qa/scripts/qa-render.mjs http://localhost:3210
```

반드시 레포 루트에서 (playwright를 여기서 찾는다). 한 바퀴 1분쯤 걸린다.
라우트를 안 주면 홈·목록·쇼츠·소개에 프로젝트 하나·글 하나를 사이트에서
찾아 더한다. 320 / 390 / 834 / 1280 네 폭 + reduced-motion 한 번.

**지적(FAIL)이면 exit 1.** 재는 것:

- **CSS가 붙었는지** (body 배경) — 서버가 덜 뜬 화면을 재고 "통과"라고 한 적이
  있다. 이게 안 붙었으면 나머지 수치는 전부 거짓이다.
- 가로 넘침 0 / 화면 밖으로 나간 요소
- **아이콘만 있는 컨트롤의 탭 영역 44×44** — `.hit::after { inset: -6px }`처럼
  가상 요소로 넓힌 것도 더해 잰다. `-m-2.5`로 가로까지 음수를 주면 끝에서
  삐져나가니 세로만 상쇄하고 가로는 패딩으로.
- 아이콘만 있는 컨트롤의 접근 이름(`aria-label`)
- 본문 대비 4.5:1 (큰 글자 3:1) — 조상까지 올라가 배경을 찾아 계산한다
- **콘솔 에러**와 4xx/5xx 요청 — 화면이 멀쩡해도 콘솔이 빨간 경우가 있었다
- 글자가 있는 링크·버튼이 24px보다 얇으면 참고(WARN)로만. 본문 속 링크까지
  44를 들이대면 목록이 무용해진다

기본으로 **사이트 밖 요청은 끊는다** (결과가 매번 같고 빠르다). 실시간
카운트(GitHub API)까지 보려면 `--external`. 그때는 403이 참고로 올라온다.

스크린샷은 `--out` 폴더(기본 `.qa/`)에 떨어진다 — **지적 0건이어도 눈으로
본다.** 아래 3번은 기계가 못 잡는다.

### 3. 눈으로 보는 것

기계가 못 잡는 것들. 실제로 되돌아온 것만 적는다.

- **태블릿(834)과 데스크탑(1280)을 꼭 본다.** 모바일만 보고 넘긴 것들이
  "데스크탑에선 아주 엉망", "태블릿에서도 깨진 화면 같아"로 되돌아왔다.
- **한쪽이 빈약하지 않은지.** 좌우로 나눈 배치에서 한쪽이 한 줄뿐이면 반대쪽에
  비해 빈약해 보인다. 오른쪽 끝이 본문 폭에 안 맞고 끊기는 것도 같은 부류다.
- **줄바꿈** — 한글은 `keep-all`. 안 넣으면 "이유 / 를"처럼 조사가 떨어져
  나간다. 웹·영상 자막·다이어그램 라벨·OG 카드 어디서나 같다. 한 낱말이 혼자
  다음 줄로 남는 것(orphan)도 본다.
- **겹침** — 같은 자리에 두 개가 그려지지 않는지. 다이어그램과 숫자 카운터가
  화면 가운데에서 겹쳤다.
- **이질감** — 나란히 있는 것들이 한 벌로 보이는지. 글자 링크·아이콘 링크·
  글자+화살표 링크 셋이 따로 놀았다. 조건부로 나타나는 요소(앱 설치 버튼)가
  줄을 들썩이게 하지 않는지도 같이 본다.
- **320px**에서 어그러지지 않는지. 360 미만은 `app/globals.css`가 `--text-*`를
  한 단계 줄인다 — 크기를 `text-[24px]`처럼 박아 쓰면 이 장치를 빠져나가니
  토큰(`text-lg` 등)을 쓴다.
- **비개발자가 읽을 수 있는지.** 본문은 그대로 두고 어려운 말에 주석을 단다
  (`components/glossary.tsx`의 `[[commit]]`). 문장을 쉽게 고쳐 설명서로 만들지
  않는다.

### 3.5 글이 쓴 대로 보이는지

```
npx tsx scripts/check-markdown.ts
```

글은 파이프라인이 매일 쓰고 사람이 읽기 전에 발행된다 — 본문 한 줄이 엉뚱하게
꾸며져도 아무도 모르는 게 이 부류의 문제다. 실제로 `6~12점, 넷 중 하나는
9~16점`의 물결표 두 개가 취소선 구분자로 먹혀 문장 가운데가 통째로 그어져
나갔다 (Jessi 지적. remark-gfm은 물결표 하나짜리 취소선을 켜 두는데 우리 글은
물결표를 범위에 쓴다 — `post-client.tsx`에서 껐다).

검사기는 화면과 **같은 파서 설정**으로 글을 읽어, 우리가 쓰지 않는 서식
(취소선·굵게·기울임·표·raw HTML)이 나오면 지적한다. 지적이 있으면 exit 1.
파이프라인도 매 실행에서 돌려 홈의 "지난 실행"에 `warn` 줄로 남긴다.

기호를 글에서 escape하지 않는다 — 범위 표기가 틀린 게 아니라 파서 설정이
틀린 것이었다. 같은 일이 생기면 먼저 "파서를 고칠 수 있나"를 본다.

### 4. 데이터가 말이 되는지

화면 두 곳이 같은 것을 말하면서 다른 숫자를 대면 그건 버그다.

- **같은 걸 보고 갱신하는지.** 통계 줄과 잔디가 각자 세던 시절 "오늘 커밋 57"
  옆에서 격자는 새벽에 끊겨 있었고, 합계 399와 이번 주 365가 따로 적혔다.
  지금은 `lib/commit-hours.ts` 한 곳에서 센다.
- **오래된 값을 실시간처럼 보여주지 않는지.** "지난 실행"이 새벽에 멈춰 있으면
  그건 신선도 문제다. 저장값 폴백이라면 그 값이 언제 것인지 따져 본다
  (`countsDate`가 오늘이 아니면 "오늘"은 0).
- **재료가 잘린 값이 아닌지.** 데브로그 frontmatter의 `commits`는 글 재료라
  `MAX_COMMITS`(20)로 잘린다. 실제 하루치는 150개도 넘는다 — 통계·잔디에
  쓰면 안 된다.
- **GitHub 공개 API는 IP당 시간당 60회다.** 방문자 브라우저가 직접 세는
  구조라 새로고침을 반복하면 403이 뜨고 조용히 저장값으로 떨어진다. 콘솔의
  403을 "괜찮은 것"으로 넘기지 말고, 숫자가 실제로 움직이는지 확인한다.
- 숫자 표기는 `lib/format.ts`의 `fmtNum` (로케일 고정 — 안 쓰면 hydration이
  깨진다).

### 5. 동작까지 확인

모양만 보고 넘기지 않는다.

- 버튼이 **뭘** 복사하는지 (공유는 사이트 메인 기준).
- 링크가 **어디로** 가는지, 리다이렉트가 몇 번인지 (옛 주소 `/log/<repo>/<date>`는
  `/p/<id>`로 한 번에).
- 주소에 드러나는 것 — 레포명·날짜를 노출하지 않는다.
- 링크 미리보기(OG): 전체 대상 공유에는 사이트 카드가, 글 주소에는 그 글 카드가
  나간다. 여백 기준은 세 카드가 같다 (`lib/og.tsx`). 폰트는 제대로 붙었는지
  실제로 뽑아 본다 (satori는 woff2를 못 읽는다 — 낡은 UA로 ttf를 받는다).

### 6. 커밋 → 푸시 → **배포 확인**

```
git push -u origin <branch>
```

그리고 **여기서 멈추지 않는다.**

1. Vercel 프로덕션 배포가 `READY`가 되는지 본다 (`list_deployments`).
2. `ERROR`면 빌드 로그를 읽고 고친다 (`get_deployment_build_logs --errorsOnly`).
3. 라이브 주소에서 바뀐 것이 실제로 보이는지 확인한다.

```
curl -s "https://vibelog.space/?cb=$RANDOM" | grep -o "<바뀐 마크업의 표식>"
```

푸시 성공을 "적용됐다"로 말한 탓에, 빌드가 두 번 연속 깨진 채 몇 시간을 모르고
지난 일이 있었다 (OG 카드 폰트 fetch 타임아웃 → 프리렌더 실패 → 배포 전체 중단).

## 쇼츠·영상 QA

영상은 렌더가 오래 걸리니 대본 단계에서 최대한 잡는다. 상세는
`docs/03-shorts-spec.md`.

- **TTS는 소리 나는 대로.** 숫자는 자릿수 무관 전부 한글로 풀고, 단위는 붙여
  쓰고 된소리·연음까지 반영한다 (`222건이` → `이백이십이꺼니`, `3.5초` →
  `삼쩜오초`). 표기(자막·글)는 아라비아 숫자 그대로. 목소리를 안 바꾸고 읽기를
  고치는 유일한 손잡이라 여기서 세 번 되돌아왔다.
- **강조는 문장의 절반을 넘지 않는다.** 훅은 하나만 — 전체가 칠해지면 강조가
  아니라 배경이다.
- **다이어그램이 붙은 문장엔 숫자 카운터를 띄우지 않는다** (가운데에서 겹친다).
  다이어그램은 편당 최대 2개, 이웃 편과 같은 종류 회피, 라벨 줄바꿈 확인.
- **데모 구간에 정지 화면이 없는지.** 녹화 중 스크린샷이 5초를 잡아먹어 데모
  블록이 통째로 멈춘 화면이었다 (`scripts/record.ts` — 구간 시작은 캡처 뒤).
- 실제 배포 사이트 녹화만 쓴다. 생성 그래픽(`scripts/art.ts`)은 보류 중.
- 날짜·day 라벨이 글 목록과 맞는지.

## 파이프라인 QA

- **글 날짜는 실행 시각이 아니라 "그 밤"이다** (`publishDateKST`, KST 06:00
  경계). cron이 3시간씩 밀려 9/11 글이 02:52에 발행돼 그날 낮 작업이 통째로
  빠진 적이 있다.
- **재실행이 기록을 지우면 안 된다.** 같은 날 재실행은 그날 수집 창 전체
  (`state.json`의 `daySince`)로 다시 만든다. 지난 날짜는 파이프라인이 다시
  만들지 않는다 — 품질 문제일 때만 `regen` 입력으로 명시 재생성.
- `content/` 밑은 파이프라인이 덮어쓴다. 손수정은 frontmatter `manual: true`.
- 수동 실행 뒤에는 **찍힌 날짜**를 확인한다 (자정 근처 실행이 다음 날로 찍힌
  사고가 있었다).

## 보고

고쳤다고 말할 때 같이 적는다.

- 무엇을 몇 폭에서 렌더해 봤는지, 잰 값(넘침·탭 영역·대비).
- 검증하지 **못한** 것은 못했다고 적는다 — 이 샌드박스 브라우저는
  `api.github.com`을 못 나가서 실시간 경로는 폴백 상태로만 확인된다.
- 배포 상태(READY/ERROR)와 라이브에서 확인한 표식.
